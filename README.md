# Запуск тестов
Для запуска тестов вызывать .gradlew test

# Переменные окружения**
```
./gradlew test -Pbasic.auth.username=... -Pbasic.auth.password=... -Pauth.email=... -Pauth.password=...
```

# Структура
```
src/main/java/org/testslotegrator/
  api/                # API-клиенты эндпоинтов
    specifications/   # RequestSpec: base-спека, авторизованная спека
  config/             # загрузка конфигурации
  model/              # DTO запросов/ответов
  utils/              # генераторы тестовых данных и конвертеры
src/test/java/org/testslotegrator/tests/   # тесты
src/test/resources/   # logback, allure.properties
gradle/libs.versions.toml  # version catalog (все версии в одном месте)
```

# Репорт
Подключен аллюр, собрать его можно стандартным подключенным плагином через таску allureReport и или allureServe

# Мысли
Все тесты красные, потому что баги на бэкенде несоответствие схемам предоставленным как эталонная документация(есть неиспользуемые модели, а также не хватает моделей(например ответ на списочный ендпоинт почему то проставлена модель единичного объекта)

Также есть и другие баги(например getOne не выдает данные, хотя getAll выдает игрока)

Также не совсем понятно само задание - написано, что нужно написать тестЫ!, а дальше идет как будто список шагов для одного какого то сценария

По поводу параллелизма - если бы была возможность создавать пользователя для тестов, то можно было бы запускать тесты параллельно, не мешая друг другу, в таком случае и часть кред не нужно было бы передавать через енвы, так как мы бы генерили
